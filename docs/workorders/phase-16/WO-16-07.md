## 目標

五輪模式有第四個季節「寒潮季」：水面結冰，水位暫時不升，但又冷又貴；季節結束時融冰，水位一次過上升。

## 規格

照總規格 §8 實作。重點：

1. **資料**：`D.SEASONS.cold`、`D.SEASON_ORDER16`、三種天氣和 `D.FLOOD_TEXT.thaw`，欄位和文字和總規格 §8.1、§8.2、§8.3 **逐字相同**。
2. **季節的次序**：`IE.Rounds.advance` 換季時，五輪模式用 `D.SEASON_ORDER16`。開局的季節不變（只從原本的三個選）。
3. **結冰**：`s.season === 'cold'` 時水位不升；`IE.Flood.tick` 不增加 `floodRun`，階段不惡化，「輕」的損失照常。
4. **不能潛水**：寒潮季的出牌和差事不出現 `dive`。
5. **融冰**：由 `cold` 換到下一季的那一晚，`s.water += ECON16.thaw`，報告加一行 `D.FLOOD_TEXT.thaw`。
6. **畫面**：`weather-fx.js` 加 `cold`、`sleet`、`snow`、`icelock`；減少動態效果時是靜態的。
7. **舊模式**：先檢查有沒有程式列舉 `D.SEASONS` 的鍵（例如隨機選季節）。有的話改成用 `D.SEASON_ORDER`，確保舊模式不會抽到 `cold`，亂數的次序也不變。

## 驗收條件

1. `node tools/test.js` 全部通過，包括 `tools/tests/cold.test.js`，測試名稱：
   - `寒潮：五輪模式的季節次序是 storm、heat、acid、cold`
   - `寒潮：開局不會是寒潮季`
   - `寒潮：寒潮季水位不升，floodRun 不增加`
   - `寒潮：寒潮季沒有潛水的卡`
   - `寒潮：換季時融冰，水位加 thaw`
   - `寒潮：舊模式的季節次序不變，不會進入寒潮季`
   - `資料：D.SEASONS.cold 和三種天氣和總規格逐字相同`
2. `node tools/sim.js 20` 的輸出和合併前**完全相同**。
3. `node tools/sim-rounds.js 200` 可以跑完；在 PR 貼出：遇到寒潮季的局數比例、通關率。
4. `node tools/smoke.js`、`node tools/smoke-rounds.js` 通過；`smoke-rounds.js` 加入：把 `s.season` 設為 `cold` 之後，場景沒有 JS 錯誤，水位條的數字在下一晚沒有上升。
5. 截圖（桌面和手機）：寒潮季的白天、三種天氣各一張，存在 `docs/shots/wo-16-07-*.png`。
6. `node tools/build.js` 之後提交 `dist/`。
