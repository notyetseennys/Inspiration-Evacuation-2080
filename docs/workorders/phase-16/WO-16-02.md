# WO-16-02：工作是罕有的差事（規則）

| 項目 | 內容 |
|---|---|
| 期數 | 第十六期甲段（總規格 §3） |
| 依賴 | WO-16-01 |
| 規模 | 中（約 280 行） |
| 分支 | `gemini/wo-16-02-gigs` |
| 可以改的檔案 | `game/js/rounds.js`、`game/js/data-rounds.js`（加 `D.GIG_TEXT`、`D.GIG_FRIEND`、生活卡 `rest`）、`game/js/story.js`（只加 `fx.gig`）、`game/js/jobs2.js`（報酬）、`game/js/auto.js`、`tools/sim-rounds.js`、新檔 `tools/tests/gigs.test.js`、`dist/` |
| 不可以改 | 介面檔；小遊戲的檔案（`micro-*.js`）；`tools/tests/spec.test.js` |

## 目標

五輪模式裏，小遊戲不再每天出現。玩家要有「差事」才可以工作；差事來自每輪的配給、故事和朋友，會過期。每一次工作的報酬更重。

## 規格

照總規格 §3 實作，重點如下。

### 1. 狀態和資料

- `s.gigs = []`（`newRun` 在五輪模式建立；舊存檔由 `IE.Rounds` 補上）。
- `D.GIG_TEXT` 和總規格 §3.5 **逐字相同**。
- `D.GIG_FRIEND`：每位朋友介紹的小遊戲。

| 朋友 | 小遊戲 |
|---|---|
| `dj` | `busk` |
| `ho` | `label` |
| `ken` | `salvage` |
| `miu` | `clinic` |
| `fong` | `busk` |
| `chan` | `dive` |
| `yu` | `delivery` |
| `mary` | `garden` |

- 生活卡 `rest`：`{ id: 'rest', kind: 'rest' }`，名稱「在家發呆」，說明「甚麼都不做。這在浮城是一種奢侈。」，效果：火花 +`ECON16.restSpark`。

### 2. `IE.Rounds`

| 函數 | 行為 |
|---|---|
| `addGig(s, c)` | 加入一個差事（補上 `night`）；已經有 `ECON16.gigMax` 個就不加，回傳 `{ ok: false }` |
| `offer(s)` | 總規格 §3.1 的三張卡；第一張是差事時，卡的資料加上 `gig: 那個差事` |
| `useGig(s, micro)` | 選了差事的卡之後呼叫：移除最舊而且 `micro` 相同的差事 |
| `expireGigs(s)` | 每天開始時呼叫：移除超過 `ECON16.gigKeep` 天的差事，回傳被移除的（給白天面板顯示） |

- 每輪第一天：`addGig(s, { micro: 從 work 類抽, from: 'round' })`。
- `story.js`：選項的 `fx.gig` 是字串時呼叫 `addGig(s, { micro, from: 'story', x: 選項的 label })`。現在的故事資料沒有 `fx.gig`，所以這一步暫時不會發生；測試用假資料。
- 和朋友聊天之後：用局內的亂數（`R.rand(s)`）按 `ECON16.friendGig` 決定是否 `addGig(s, { micro: D.GIG_FRIEND[npc], from: 'friend', x: 朋友的名字 })`。

### 3. 報酬（`jobs2.js`）

五輪模式裏，經由差事做的小遊戲：

- 收入乘 `ECON16.gigPay`；
- 評級 B 或以上必定得到一張卡；A 是 ★2，S 是 ★3，SS 是 ★4（比原本的星級高才改）；
- 卡的 `origin` 是 `{ kind: 'work', x: 小遊戲的名稱 }`。

### 4. 模擬器

`tools/sim-rounds.js` 的機械人：有差事的卡就選它（照舊做）；沒有就照原本的偏好。在輸出加一行：每局平均做了幾次小遊戲、平均有幾個差事過期。

## 驗收條件

1. `node tools/test.js` 全部通過，包括 `tools/tests/gigs.test.js`，測試名稱：
   - `差事：每輪第一天得到一個`
   - `差事：沒有差事時，offer 不會出現小遊戲的卡`
   - `差事：有差事時，第一張是那個小遊戲，選了之後差事用掉`
   - `差事：超過 gigKeep 天就過期`
   - `差事：最多 gigMax 個`
   - `差事：故事的 fx.gig 會加入差事`
   - `報酬：經由差事做的小遊戲，收入乘 gigPay，B 或以上必定有卡`
   - `資料：D.GIG_TEXT 和總規格逐字相同`
2. `node tools/sim.js 20` 的輸出和合併前**完全相同**。
3. `node tools/sim-rounds.js 200` 可以跑完。通關率**預期會變**；在 PR 貼出合併前後的通關率、平均收入、每局小遊戲的次數。數值由 WO-16-05 校準，這張工單不用調。
4. `node tools/smoke.js` 通過。`node tools/smoke-rounds.js`：如果因為白天沒有小遊戲的卡而失敗，把失敗的項目和原因寫在 PR，由 Claude 修訂測試；**不要自己改測試**。
5. `node tools/build.js` 之後提交 `dist/`。

## 不要做

- 不要做介面；不要改小遊戲本身。
- 不要調整 `D.ECON` 原有的數值。
