## 目標

五輪模式裏，每一張卡都記得自己的來歷；素材庫滿了不再自動丟掉，由玩家選一張放進回憶。這張工單只做規則，介面在 WO-16-04。

## 規格

照總規格 §2 實作，重點如下。

### 1. 資料

`data-rounds.js` 加入 `D.ORIGIN`、`D.CARD_TEXT`、`D.ECON16`，文字和數值要和總規格 §2.1、§2.5、§3.4 **逐字相同**。

### 2. `IE.Cards`（新檔 `cards.js`，在 `rules.js` 之後載入）

| 函數 | 行為 |
|---|---|
| `origin(s, o)` | 由 `{ kind, x, npc }` 組成完整的 `origin`：`night` 取 `s.night \|\| 0`，`text` 用 `D.ORIGIN[kind]` 取代 `{n}`、`{x}`；`o` 是空值就回傳 `null` |
| `putDown(s, uid)` | 總規格 §2.2 |
| `autoPutDown(s)` | 在 `s.over` 時，用舊的自動丟棄規則選一張（最殘的；同樣殘就丟價值最低而且用過的），但不選遺物；放進 `s.memory`；重複到不再超過上限 |
| `noteWork(s, uids, title)` | 總規格 §2.3 |
| `relics(s, npcId)` | 總規格 §2.4 |
| `ensure(s)` | 舊存檔：沒有 `s.memory` 就建立空陣列，`s.over` 設為 `false`；每張卡沒有 `works` 就補 `[]` |

### 3. `R.addCard(s, idOrCard, origin)`

- 五輪模式：照總規格 §2.2，不丟棄，回傳 `{ card, dropped: null, over }`。
- 其他模式：行為和現在**完全相同**（包括回傳值）。
- 所有呼叫 `addCard` 的地方，在五輪模式要傳入 `origin`：

| 檔案 | 位置 | `origin` |
|---|---|---|
| `rules.js` 的 `newRun` | 角色的卡、`D.STARTER` | `{ kind: 'start' }` |
| `story.js` | 故事選項的 `fx.card`、筆記的卡 | `{ kind: 'story', x: 選項的 label }` |
| `jobs2.js` | 小遊戲得到的卡 | `{ kind: 'work', x: 小遊戲的名稱 }` |
| `rounds.js` | 出國選的卡 | `{ kind: 'trip', x: 地區的名稱 }` |
| `rounds.js` | 素材包、複製 | `{ kind: 'shop' }`、`{ kind: 'craft' }` |
| `world.js` | 古董店 | `{ kind: 'shop' }` |
| `stages.js`、`create.js` | 複製、合併、孢子 | `{ kind: 'craft' }` |
| 朋友送的卡（`R.applyChat` 等） | | `{ kind: 'friend', x: 朋友的名字, npc: id }` |

舊模式的呼叫不用改（`rules.js` 第 1273、1408、1896 行附近在兩種模式都會執行的，要用 `s.mode === 'rounds'` 判斷才傳入）。

### 4. 流程

- `IE.Rounds` 進入 `night` 之前：`s.over` 為 `true` 就不進入，回傳 `{ ok: false, msg: D.CARD_TEXT.overHead }`。
- `tools/sim-rounds.js` 和 `IE.Auto`：每次得到卡之後呼叫 `IE.Cards.autoPutDown(s)`。
- 夜晚打出具名組合的地方（`craft.js` 回傳結果之後、`rounds.js` 記分的地方）呼叫 `noteWork`。
- 收藏朋友的地方呼叫 `relics`。

## 驗收條件

1. `node tools/test.js` 全部通過，包括新的 `tools/tests/cards.test.js`，測試名稱：
   - `卡的來歷：五輪模式開局的卡都是 start`
   - `卡的來歷：故事的卡記下選項的名字和第幾晚`
   - `回憶：超過上限時不丟棄，s.over 為 true`
   - `回憶：putDown 之後回到上限，卡在 s.memory`
   - `回憶：遺物不可以放下`
   - `作品：noteWork 最多記 3 個，不重複`
   - `遺物：朋友被收藏之後，那位朋友的卡變成遺物`
   - `舊模式：addCard 的回傳值和丟棄規則不變`
   - `資料：D.ORIGIN、D.CARD_TEXT 和總規格逐字相同`
2. `node tools/sim.js 20` 的輸出和合併前**完全相同**。
3. `node tools/sim-rounds.js 200` 可以跑完；通關率和合併前相差不超過 3 個百分點（規則上只是把丟棄改成放進回憶，結果應該幾乎一樣；有差別要在 PR 說明原因）。
4. `node tools/smoke.js`、`node tools/smoke-rounds.js` 通過；`node tools/build.js` 之後提交 `dist/`。
