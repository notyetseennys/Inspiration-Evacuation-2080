# WO-16-05：開局的卡和數值校準

| 項目 | 內容 |
|---|---|
| 期數 | 第十六期甲段（總規格 §3.4、§5、§7） |
| 依賴 | WO-16-01 至 04 |
| 規模 | 小（約 150 行，加上校準紀錄） |
| 分支 | `gemini/wo-16-05-calibration` |
| 可以改的檔案 | `game/js/rules.js`（只改五輪模式開局的卡）、`game/js/data-rounds.js`（`D.ECON`、`D.ECON16` 的數值）、`tools/sim-rounds.js`、`tools/tests/spec.test.js`（只改這次校準的數值，同一個 PR）、新檔 `docs/workorders/phase-16/CALIBRATION.md`、`dist/` |
| 不可以改 | 規則的邏輯 |

## 目標

五輪模式開局只有很少的卡；用模擬器調整數值，令難度回到第十五期校準時的水平，並且每一輪都有足夠的卡可以創作。

## 規格

1. **開局的卡**：五輪模式的 `newRun` 只加入角色的 `bg.cards`，再從 `D.STARTER` 按次序取 `ECON16.startStarter` 張。舊模式不變。
2. **校準的目標**（`node tools/sim-rounds.js 500`，三種機械人）：

| 指標 | 目標 |
|---|---|
| 一般機械人通關率 | 和第十五期 `CALIBRATION.md` 記錄的數字相差不超過 5 個百分點 |
| 第一晚的素材庫 | 4 至 6 張 |
| 第三晚（第一輪 Boss）的素材庫 | 8 至 11 張 |
| 第十五晚的素材庫 | 18 至 26 張 |
| 每局親手可玩的小遊戲 | 5 至 8 次 |
| 每局過期的差事 | 平均不多於 1 個 |
| 第一輪被淘汰 | 不多於 12% |

3. **可以調的數值**，按這個次序嘗試，每次只改一項：
   1. 第一輪三晚的目標（`D.ECON` 裏的夜晚目標）；
   2. `ECON16.gigPay`、`friendGig`、`gigMax`、`gigKeep`；
   3. 素材包的價錢和每輪的房租。
4. **校準紀錄** `CALIBRATION.md`：每一次改動一行：改了甚麼、之前和之後的指標。

## 起點（WO-16-02 合併之後，400 局）

一般機械人的通關率是 55%（第十五期校準時約 36%），每局小遊戲 6.6 次，過期的差事 0 個。通關率偏高的原因：工作少了，消耗也少了；差事的收入是 2.2 倍；「在家發呆」加火花而沒有代價。校準時先看 `gigPay` 和 `restSpark`，再看第一輪的目標。

## 驗收條件

1. `node tools/test.js` 全部通過（`spec.test.js` 只改這次校準的數值）。
2. `node tools/sim.js 20` 的輸出和合併前**完全相同**。
3. `node tools/sim-rounds.js 500` 達到上表全部目標；輸出貼在 PR。達不到的項目要說明試過甚麼，由 Claude 決定是否改規則。
4. `node tools/smoke.js`、`node tools/smoke-rounds.js` 通過；`node tools/build.js` 之後提交 `dist/`。
