| 項目 | 內容 |
|---|---|
| 期數 | 第十六期甲段（總規格 §7） |
| 依賴 | WO-16-01（回憶）；和 WO-16-03、04 互不依賴 |
| 規模 | 大（約 550 行） |
| 分支 | `gemini/wo-16-06-flood` |
| 可以改的檔案 | 新檔 `game/js/flood.js`、`game/js/data-rounds.js`（`D.FLOOD_TEXT`、`D.SERVICES16`、`D.ECON16` 的新鍵、`D.CARD_TEXT.lostFlood`）、`game/js/rounds.js`、`game/js/auto.js`、`game/js/ui.js`、`game/js/main.js`、`game/css/polish.css`、`game/index.html`、`tools/sim-rounds.js`、`tools/smoke-rounds.js`（只加新的檢查）、新檔 `tools/tests/flood.test.js`、`docs/shots/`、`dist/` |

## 目標

五輪模式裏，水位是每天看得見的壓力。水淹到家的後果由輕到重：受傷、被水帶走一張卡、失去住所。玩家可以花錢搬上一層，錢不夠就只能看着水上來。

## 規格

照總規格 §7 實作。重點：

### 1. `IE.Flood`（新檔 `flood.js`，在 `rounds.js` 之前載入）

| 函數 | 行為 |
|---|---|
| `stage(s)` | 回傳現在的階段（`dry`、`warn`、`light`、`medium`、`heavy`），已經計入抽水泵和角色特性 |
| `tick(s)` | 每晚白天開始時呼叫一次：更新 `s.floodRun`、`s.flood`，套用「輕」的損失；「中」設 `s.floodPick = [三個 uid]`；「重」執行失去住所。回傳報告（`R.report` 的格式） |
| `pick(s, uid)` | 「中」：把那張卡移到 `s.memory`，加 `lost: 'flood'` 和 `lostNight`；清除 `s.floodPick` |
| `autoPick(s)` | 模擬器和 `IE.Auto`：放下三張之中價值最低的 |
| `deckMax(s)` | 素材庫的上限（沒有住所時減 `ECON16.homelessDeck`）；`IE.Cards` 的上限改為呼叫它 |
| `services(s)` | 回傳現在可以買的 `moveup`、`rehouse`（附價錢和是否買得起） |
| `buy(s, id)` | 扣錢並套用效果 |

- `s.floodPick` 有值時不可以選生活卡，也不可以進入夜晚。
- 抽的三張卡用局內的亂數（`R.rand(s)`）；素材庫不足三張就全部列出；只有遺物就跳過「帶走一張卡」。
- 失去的靈感物件用局內的亂數抽；沒有可以失去的就跳過。
- 所有文字用 `D.FLOOD_TEXT`，和總規格 §7.4 **逐字相同**。

### 2. 介面

照總規格 §7.5 的表，class 和 `data-do` 要完全相同。

- 水位條放在狀態列，常駐。這是第十六期唯一新增的常駐欄位，要小而清楚。
- 「水帶走一張卡」的視窗裏，卡可以翻到卡背看來歷（WO-16-04 已經合併的話沿用 `[data-do="cardback"]`；未合併就先不做，並在 PR 說明）。
- 被水帶走的卡在回憶裏，卡背多一行 `D.CARD_TEXT.lostFlood`（同樣視乎 WO-16-04）。

### 3. 模擬器

`tools/sim-rounds.js` 加一行輸出：每局平均淹了幾晚、被水帶走幾張卡、失去住所的局數比例、平均搬了幾次。機械人：有錢而且階段是 `warn` 或以上就買 `moveup`；沒有住所而且有錢就買 `rehouse`。

## 驗收條件

1. `node tools/test.js` 全部通過，包括 `tools/tests/flood.test.js`，測試名稱：
   - `水位：差一層以內是預警，沒有損失`
   - `水位：淹第一晚是輕，身體和火花減少`
   - `水位：連續第二晚是中，三張卡選一張進入回憶，標記 lost`
   - `水位：連續第三晚是重，住到天橋下，失去一件物件，素材庫上限減少`
   - `水位：遺物不會被水帶走`
   - `水位：抽水泵令階段推遲一級`
   - `水位：搬上一層之後 floodRun 歸零，價錢按樓層計`
   - `水位：住天橋下可以租回一個單位`
   - `水位：舊模式不受影響`
   - `資料：D.FLOOD_TEXT 和總規格逐字相同`
2. `node tools/sim.js 20` 的輸出和合併前**完全相同**。
3. `node tools/sim-rounds.js 200` 可以跑完；在 PR 貼出通關率和新加的那一行。通關率預期會下降，由 WO-16-05 校準。
4. `node tools/smoke.js`、`node tools/smoke-rounds.js` 通過；`smoke-rounds.js` 加入：
   - 狀態列有 `.rd-water`，文字包含「水位」和「樓」；
   - 把 `s.water` 設到比 `s.floor` 低 0.5 之後進入下一晚，出現 `.rd-flood` 的預警；
   - 連續淹兩晚後出現 `.rd-floodpick`，按一張之後 `s.memory` 多了一張 `lost === 'flood'` 的卡；
   - 手機 390px 沒有橫向捲動。
5. 截圖（桌面和手機）：水位條的四個階段、帶走一張卡、失去住所、市集的兩項服務，存在 `docs/shots/wo-16-06-*.png`。
6. `node tools/build.js` 之後提交 `dist/`。

## 不要做

- 不要改舊模式。
