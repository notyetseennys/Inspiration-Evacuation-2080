### 2. 規則層（`rounds.js`，全部是純函數，可以在 Node 測試）

全部加進 `IE.Rounds` 的匯出。除了 `prologueTarget` 會自己開一個用完即棄的局面，其餘都只讀寫傳入的局面。**不可以用 `Math.random`。**

| 函數 | 行為 |
|---|---|
| `prologueRun()` | 回傳用完即棄的局面 `p`：`R.newRun({ bg: PROLOGUE.bg, season: PROLOGUE.season, seed: PROLOGUE.seed, mode: 'rounds', meta: { runs: 0 } })`，然後：`p.prologue = true`；`p.objects = []`；`p.cards = []`，再用 `R.addCard(p, id, { kind: 'prologue' })` 按 `PROLOGUE.cards` 的次序加入四張；`p.weather = { id: PROLOGUE.scene.weather, day: p.day }`（和 `rules.js` 的格式相同）；`p.phase = 'night'` |
| `prologueStart(p)` | 用 `IE.Create.start(p, 'normal')` 開創作之夜，然後覆蓋：`ses.hand` = 四張卡的 uid（`PROLOGUE.cards` 的次序）；`ses.deck = []`；`ses.used = []`；`ses.plays = 3`；`ses.discards = 0`；`ses.stage = { kind: 'prologue', name: PROLOGUE.stageName, target: prologueTarget(), rules: [], index: 0 }`；`ses.prologueStep = 0`。回傳 `ses` |
| `prologueStep(p)` | 回傳現在這一步：`{ i, uids, say, after }`（`uids` 是這一步要按的 uid，按次序）；三步都完成就回傳 `null` |
| `prologueNext(p, sel)` | `sel` 是介面上已經選了的 uid（按次序）。回傳 `{ uid }`（下一張要按的卡）或 `{ play: true }`（這一步選齊了，要按「下筆」）。`sel` 和這一步的開頭不符就回傳 `{ reset: true }` |
| `prologueAfterPlay(p)` | 每一筆之後呼叫：`ses.hand` 還原為四張卡（原來的次序）；`ses.deck = []`；`ses.used = []`；`ses.prologueStep += 1` |
| `prologueTarget()` | 開一個新的 `prologueRun()`，照三步用 `IE.Create.play` 下三筆（每筆之後 `prologueAfterPlay`），記下累計分數 `cum1`、`cum2`、`cum3`，回傳 `Math.round((cum2 + cum3) / 2)`。這樣第三筆一定剛剛達標，而且分數怎樣校準都成立。**不可以把目標寫成常數** |
| `prologueFinish(p)` | 收工：回傳 `{ title, total, strokes }`（`title` 用 `IE.Create.workName(ses.log, p)`；`total` 是 `ses.total`；`strokes` 是 `ses.paintStrokes || []`，在 Node 測試裏沒有畫，所以可以是空的），然後 `p.session = null`。**不呼叫 `IE.Create.finish`、`IE.Stages.settle`**（見陷阱 2） |
| `prologueCarry(s)` | 把四張卡的**新複本**加進正式的局 `s`：`R.addCard(s, id, { kind: 'prologue' })`，耗損是 0。回傳四張卡 |
| `reveal(s)` | 引導局要顯示甚麼。不是引導局（`!s.guided`）就全部是 `true`、`cardsMax` 是 `Infinity`。引導局按下表 |
| `guidedOptions(s, ch)` | 回傳要顯示的選項編號（`ch.options` 裏的位置）。引導局而且還沒有回答過故事章（`!(s.story && s.story.log && s.story.log.length)`）：生存、為別人、巔峰各一個（`opt.side` 是 `survive`、`others`、`peak`；同一種有幾個就取第一個不是 `extreme` 的；沒有就用第一個；仍然沒有，就按原來的次序補上其他選項，直到三個），按原來的次序排列。其他情況回傳全部編號 |
| `newHints(s, rep)` | 引導局：回傳 `rep.deltas` 裏 `cr`、`spark`、`soul` 之中不是 0、而且 `s.hinted` 裏未有的鍵（次序 `cr`、`spark`、`soul`）。不是引導局回傳 `[]`。**不改 `s`** |

### 3. 序章之夜的介面（`craft.js`、`desk.css`）

## 常見陷阱（請逐條確認）

1. **序章不可以存檔**。`craft.js` 的 `persist()` 會呼叫 `IE.Game.save()`；序章時它必須甚麼都不做。`Game.state` 在序章期間保持 `null`。
2. **序章不可以呼叫 `IE.Create.finish` 或 `IE.Stages.settle`**。`settle` 會用 `stage.kind` 查獎金表（`IE.Rounds.nightReward`），`'prologue'` 不在表內。用 `IE.Rounds.prologueFinish`。
3. **`sortedHand()` 會把手牌按情緒排序**。序章要保持 `PROLOGUE.cards` 的次序，否則發光的卡會跳來跳去。
4. **卡上的「來歷」按鈕會讀 `IE.Game.state`**，序章時是 `null`。序章不顯示這個按鈕。
5. **目標不可以寫成常數**。分數會在 WO-16-05 校準時改變；`prologueTarget()` 每次用規則算，第三筆才會剛好達標。
6. **開場的關卡介紹要多按一下**才消失。序章不顯示它，否則「四次點擊」做不到。
7. **`guided` 只在 `main.js` 設**。改 `rules.js` 的 `newRun` 會令模擬器的輸出改變。
8. **隱藏不等於取消**。被隱藏的部分規則照常運作（例如第一晚不顯示租金，租金仍然照計）。後果和損失（水淹、過期的差事、沒有差事）永遠顯示。
9. **只限制生活卡顯示的張數**。不可以改 `IE.Rounds.offer`：模擬器用它，改了輸出就會改變。
10. **`storyModal` 的 `data-i` 要保持原來的編號**。過濾之後重新編號，玩家選的會是另一個選項。
11. **測試的開關要在第一次載入之前設好**。`smoke.js` 用 `addInitScript`；`smoke-rounds.js` 在 `reload()` 之前的 `evaluate` 裏設。
12. **序章的邏輯不可以用 `Math.random`**。畫面的特效（火花、雨）可以。
13. **文字不可以改**。字數檢查不通過，在提交說明寫明是哪一句、多少字，由 Claude 決定。
14. 第二局起（`meta.runs > 0`）和經典模式，標題頁、開局頁、白天面板、創作桌都要和現在**完全相同**。
15. **不要刪第十七期的程式**：`main.js` 的 `openEra`、`openSalvage`、局末的沉積結算，`ui.js` 的年表和打撈按鈕、`IE.EraUI.dayExtras`，`craft.js` 的「排練」「劇本」。合併衝突時保留兩邊。
