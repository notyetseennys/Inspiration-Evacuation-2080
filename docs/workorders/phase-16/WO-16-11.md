# WO-16-11：頭五分鐘（序章之夜和逐步打開的介面）

| 項目 | 內容 |
|---|---|
| 期數 | 第十六期乙段（總規格 §11） |
| 依賴 | WO-16-09、WO-16-10 |
| 規模 | 中（約 400 行） |
| 分支 | `gemini/wo-16-11-first-five` |
| 可以改的檔案 | `game/js/main.js`、`game/js/ui.js`、`game/js/craft.js`、`game/js/rounds.js`（只加序章的開局和「第幾晚顯示甚麼」）、`game/js/data-rounds.js`（`D.PROLOGUE`）、`game/css/polish.css`、`tools/smoke-rounds.js`、新檔 `tools/first-five.js`、新檔 `tools/tests/prologue.test.js`、`docs/shots/`、`dist/` |
| 不可以改 | 規則和數值；第二局起的流程；舊模式 |

## 目標

新玩家按「開始」之後，60 秒內下第一筆並且成功，五分鐘內完成第一晚、看到自己的畫、遇到第一個選擇。要讀的字比現在少三分之二。

## 規格

照總規格 §11 實作。重點：

### 1. `D.PROLOGUE`（文字由 Claude 寫，逐字使用）

```js
D.PROLOGUE = {
  bg: 'copywriter', seed: 2080,
  title: '靈感撤離 2080',
  tagline: '水每天都在上來。你還有今晚可以畫。',
  cards: ['dk_warmth1', 'dk_warmth2', 'dk_machine1', 'dk_warmth_machine'],
  steps: [
    { pick: [0, 1], say: '這兩張都有人情，接得上。按它們，再按下筆。' },
    { pick: [0, 1, 2], say: '人情的對面是機械。相反的情緒，是轉。' },
    { pick: [0, 1, 2, 3], say: '最後一張有機械也有人情。回到開頭，是合。' },
  ],
  done: '這就是起承轉合。之後每一晚，都由你決定次序。',
  hint: { cr: '錢：交租用。', spark: '火花：分數的倍數。', soul: '靈魂：太重，外星人不要你。' },
};
```

- 四張卡是：一碗糖水兩個人、摺紙船、為誰撐傘的機械人、人機之間。
- `cards` 的四張必須令三步分別是「承接」、「峰迴路轉」、「起承轉合」。如果 `dk_*` 的 id 和這裏不同，用情緒相同的卡代替，並在 PR 說明；`tools/tests/prologue.test.js` 用 `IE.Desk.analyze` 檢查三步的結構。
- 序章之夜的目標分數定為第三筆分數的 60%（用固定的種子算出來，寫成常數），令三筆必定達標。
- 序章不計入 15 晚：完成之後，手上的四張素材留在素材庫，然後才開始第一輪第一晚。

### 2. 序章之夜的介面

- 只有畫、稿紙、手牌、下筆。其餘（評審、KPI、改稿、能力、「⋯」選單、速度）隱藏。
- 這一步要按的卡發光（`.dk-card.is-guide`），其他卡不可以按。
- 教學的句子在稿紙上方（`.dk-say`），一次一句；做了才前進，沒有「下一步」和「跳過」。
- 第三筆之後顯示作品頁和 `done` 的一句。

### 3. 第一次開遊戲

- `meta.runs === 0`：標題頁只有名字、`tagline` 和「開始」；按「開始」直接進入序章。
- 開局頁、玩法、收藏、扭蛋、每日挑戰、人才檔案由第一局完成（無論結果）之後才出現。
- 設定裏加一項「重看序章」。

### 4. 逐步打開（只在 `meta.runs === 0` 的那一局）

- 白天面板照總規格 §11.1 的表，按晚數顯示。純函數 `IE.Rounds.reveal(s)` 回傳 `{ cards, rent, shop, judge, weather, collector, feed, all }`，介面只按它顯示；規則照常運作（例如租金照計，只是第一晚不顯示）。
- 第一個故事抉擇只顯示三個選項：生存、為別人、巔峰各一（沒有那一類就按原來的次序補上）。
- `hint` 的三句各在那種資源第一次改變時出現一次，位置在數值旁邊。

### 5. 量度工具 `tools/first-five.js`

用 Playwright 以手機 390×844 開啟 `dist/`，清空儲存，模擬新玩家（只按發光的東西；沒有發光的就按第一個可以按的），輸出總規格 §11.2 那張表的每一項實際數字，超出上限就以非零的狀態結束。

## 驗收條件

1. `node tools/test.js` 全部通過，包括 `tools/tests/prologue.test.js`：
   - `序章：三步的結構是承接、峰迴路轉、起承轉合`
   - `序章：三筆都達標`
   - `序章：每句教學不多於 30 個字，資源的說明不多於 20 個字`
   - `序章：完成之後四張素材留在素材庫，晚數是第一晚`
   - `逐步打開：第一局第一晚只有夜景、目標和兩張生活卡`
   - `逐步打開：第二局起全部顯示`
2. `node tools/first-five.js` 通過，在 PR 貼出輸出。
3. `node tools/sim.js 20` 的輸出和合併前完全相同；`node tools/sim-rounds.js 200` 的通關率和合併前相同（模擬器不經序章）。
4. `node tools/smoke.js`、`node tools/smoke-rounds.js` 通過（原有的檢查用 `meta.runs ≥ 1` 的狀態開始；另加一段由全新的儲存開始，走完序章）。
5. 截圖（手機）：標題頁、序章三步、作品頁、第一個抉擇、第一晚的白天面板，存在 `docs/shots/wo-16-11-*.png`。
6. `node tools/build.js` 之後提交 `dist/`。

## 不要做

- 不要改文字（`D.PROLOGUE` 逐字使用）。
- 不要加「跳過教學」：序章不到一分鐘。
- 不要動第二局起的介面。
