# 第十六期總規格：每一張卡都是一段經歷

製作人的方向（2026-11-10）：

- 故事劇情是主軸；
- 每一張卡都是收藏回來的，有來歷，玩家會珍惜；
- 開局簡單，手上沒有甚麼卡；卡由故事的選擇、工作（小遊戲）、旅遊、市集和朋友得來；
- 工作（小遊戲）變成罕有的差事，而且要更好玩；
- 整個遊戲要極具深度、人性化、有黑色諷刺、有血有淚。

這份文件是第十六期規則、數值和文字的唯一來源。世界觀和語氣以 `docs/WORLD.md` 為準，錢的尺度以 `docs/ECONOMY.md` 為準，第十五期的規則（`docs/workorders/phase-15/README.md`）沒有被這份文件改動的部分繼續有效。

**所有改動只在五輪模式（`s.mode === 'rounds'`）生效。舊模式（`standard`、`long`）的結果必須不變。**

---

## §1 設計的三條原則

1. **卡 = 經歷。** 每張卡記得自己是哪一晚、在哪裏、因為甚麼得來的。玩家選的人生，決定他能創作甚麼。
2. **稀有才珍貴。** 工作不是每天都有；有差事的時候，怎樣做比做得多好更重要。
3. **每個系統都有代價。** 沒有「正確」的選項：順從有錢但有愧，反抗有尊嚴但捱餓，幫人會令自己更難。諷刺來自制度一本正經的語氣，不是來自旁白的說教。

第十六期分兩段：

| 段 | 內容 | 工單 |
|---|---|---|
| 甲 | 在現有的創作桌上，做卡的來歷、回憶、差事和小遊戲的抉擇 | WO-16-01 至 05 |
| 乙 | 把原型第五版的創作桌（起承轉合、75 張有卡面的卡、圖鑑）搬入主遊戲 | WO-16-06 起，甲段完成後才寫 |

## §2 卡的來歷（WO-16-01）

### 2.1 欄位

每張卡（`s.cards` 的元素）加上：

```js
card.origin = { kind: 'story', night: 3, text: '把工作讓給舊同事的那一天', npc: null };
card.works = [];   // 這張卡參與過的具名作品，最多記 3 個（最新的在最後）
card.relic = false; // 送這張卡的朋友被收藏之後變成 true
```

`origin.kind` 的值和預設的文字 `D.ORIGIN[kind]`（`{n}` 是第幾晚，`{x}` 是來源的名字）：

| kind | 來源 | `D.ORIGIN[kind]` |
|---|---|---|
| `start` | 開局 | `來浮城之前就帶在身上` |
| `story` | 故事的選擇 | `第 {n} 晚之前：{x}` |
| `work` | 工作 | `第 {n} 晚之前，做「{x}」的時候留下的` |
| `trip` | 旅遊 | `第 {n} 晚之前，從{x}帶回來` |
| `friend` | 朋友 | `{x}給你的` |
| `shop` | 市集 | `第 {n} 晚之後，在市集買的` |
| `craft` | 複製、合併 | `第 {n} 晚之後，自己做出來的` |

- `R.addCard(s, idOrCard, origin)` 加第三個參數。`origin` 可以只給 `{ kind, x, npc }`，`night` 和 `text` 由 `IE.Cards.origin(s, o)` 補上（`night` 取 `s.night`，沒有就是 0）。
- 不給 `origin` 時（舊模式、舊存檔）：`card.origin` 是 `null`，介面不顯示來歷。
- 故事的卡：`x` 取那個選項的 `label`。

### 2.2 回憶：不再自動丟棄

五輪模式裏，素材庫超過上限時不再自動丟掉：

- `R.addCard` 照常加入，回傳 `{ card, dropped: null, over: true }`，並設 `s.over = true`。
- `IE.Cards.putDown(s, uid)`：把那張卡由 `s.cards` 移到 `s.memory`（陣列，最新的在最後），回傳 `{ ok, card }`。`s.cards.length` 回到上限或以下時 `s.over = false`。
- `s.over` 為 `true` 時不可以進入夜晚（`IE.Rounds` 進入 `night` 之前檢查；模擬器和 `IE.Auto` 用 `IE.Cards.autoPutDown(s)`，規則和舊的自動丟棄相同）。
- `relic` 的卡不可以放下（`putDown` 回傳 `{ ok: false, msg: D.CARD_TEXT.relicKeep }`）。
- 回憶裏的卡不會回到手上，只可以看。

### 2.3 作品的記錄

夜晚裏打出具名組合時，`IE.Cards.noteWork(s, uids, title)` 把作品名字記在每張計分的卡的 `works`（已經有就不重複；超過 3 個就去掉最舊的）。

### 2.4 遺物

朋友被收藏時（`IE.Story` 處理收藏的地方），`IE.Cards.relics(s, npcId)` 把 `origin.npc === npcId` 的卡設為 `relic = true`，回傳這些卡。

### 2.5 文字 `D.CARD_TEXT`

| 鍵 | 文字 |
|---|---|
| `backHead` | `這張卡的來歷` |
| `worksHead` | `它參與過的作品` |
| `noWorks` | `還沒有用它完成過具名的作品。` |
| `relic` | `遺物：給你這張卡的人已經不在浮城。` |
| `relicKeep` | `這是遺物，放不下。` |
| `overHead` | `素材庫放不下了` |
| `overSub` | `選一張放進回憶。放下的卡不會消失，但不能再用。` |
| `memoryHead` | `回憶` |
| `memoryEmpty` | `你還沒有放下過任何東西。` |

## §3 工作是罕有的差事（WO-16-02）

### 3.1 差事

> 名稱：主遊戲已經有「機會」（`s.chances` 是玩家剩餘的機會，故事有 `fx.chance: ±1`）。第十六期的新概念叫「差事」，欄位用 `gig`，不可以和「機會」混用。

- `s.gigs`：陣列，每個元素 `{ micro: 'delivery', from: 'story', x: '舊同事介紹', night: 2 }`。
- 生活卡的出牌規則 `IE.Rounds.offer(s)` 改為：
  - 第一張：`s.gigs` 有元素時，是最舊的一個差事對應的小遊戲卡（卡上顯示 `D.GIG_TEXT.tag` 和差事的來源）；沒有差事時，從 `friend`、`volunteer`、`rest` 抽。
  - 第二張：從 `friend`、`life` 抽，但 `life` 之中有小遊戲的卡（`dive`、`busk`、`garden`）只在有對應的差事時才出現。
  - 第三張：照舊，但不包括小遊戲的卡。
- 新的生活卡 `rest`（種類 `rest`）：「在家發呆」，火花 +`ECON16.restSpark`。
- 玩家選了差事的卡（無論親手做還是照舊做），那個差事就用掉；沒有選，差事留到下一天，最多留 `ECON16.gigKeep` 天，過期就消失，並在白天面板顯示 `D.GIG_TEXT.expired`。

### 3.2 差事的來源

| 來源 | 規則 |
|---|---|
| 每輪開始 | 第一天給一個差事，小遊戲從 `work` 類抽（`from: 'round'`） |
| 故事的選項 | 選項的 `fx.gig: '<micro>'`（由 Claude 在 `data-story.js` 加；這張工單只做規則） |
| 朋友 | 和朋友聊天之後有 `ECON16.friendGig` 的機率得到一個（`from: 'friend'`，小遊戲取 `D.GIG_FRIEND[npc]`） |
| 上限 | 同時最多 `ECON16.gigMax` 個，滿了就不再得到 |

### 3.3 報酬

工作少了，每一次的分量要重：

- 收入：`R.applyMicro` 的收入乘 `ECON16.gigPay`。
- 素材：評級 B 或以上必定得到一張卡（原本要看評級和機率）；A 是 ★2，S 是 ★3，SS 是 ★4。卡的 `origin` 是 `{ kind: 'work', x: 小遊戲的名字 }`。

### 3.4 數值 `D.ECON16`（暫定，WO-16-05 校準）

| 鍵 | 值 | 說明 |
|---|---|---|
| `restSpark` | 0.2 | 在家發呆的火花 |
| `gigKeep` | 3 | 差事保留的天數 |
| `gigMax` | 2 | 同時持有的差事上限 |
| `friendGig` | 0.25 | 聊天之後得到差事的機率 |
| `gigPay` | 2.2 | 差事的收入倍數 |
| `startStarter` | 2 | 開局從 `D.STARTER` 取幾張（WO-16-05 才生效） |
| `stancePay` | `{ comply: 1.3, resist: 0.6, care: 0.8 }` | 抉擇對收入的倍數（§4） |

### 3.5 文字 `D.GIG_TEXT`

| 鍵 | 文字 |
|---|---|
| `tag` | `差事` |
| `from.round` | `人才發展局本季配給的工作` |
| `from.story` | `{x}` |
| `from.friend` | `{x}介紹的` |
| `left` | `還有 {n} 天` |
| `expired` | `「{x}」的差事過期了。系統已經把它分配給更積極的人。` |
| `none` | `今天沒有工作。這在浮城很正常。` |

## §4 小遊戲的抉擇（WO-16-03、WO-16-04）

現在的小遊戲只考手眼。第十六期每個小遊戲加一個**抉擇**：中途出現一個兩難，玩家用玩法本身回答（不是彈出視窗）。怎樣回答，決定得到哪一張卡。

### 4.1 立場

每次小遊戲的結果加上 `res.stance`：

| stance | 意思 | 收入 | 靈魂 |
|---|---|---|---|
| `comply` | 照制度的要求做 | ×`stancePay.comply` | 變重（`sin +1`） |
| `resist` | 不照做 | ×`stancePay.resist` | 不變 |
| `care` | 為了某個人而犧牲成績 | ×`stancePay.care` | 變輕（`atone +1`） |
| `null` | 這一次沒有遇上抉擇 | 不變 | 不變 |

- 抉擇每次都會出現（差事已經很少，每一次都要有分量）。
- 評級仍然只看手眼的表現；抉擇不影響評級，只影響收入、靈魂和卡。
- `IE.Auto`（照舊做）一律是 `comply`：不親手做，就是照制度做。這一點要在卡上寫明（`D.STANCE_TEXT.auto`）。

### 4.2 每個小遊戲的抉擇和卡 `D.STANCE[micro]`

卡的寫法和故事的卡一樣（`name`、`tags`、`value`、`star`、`medium`）；`star` 之後再按評級調整（§3.3）。

| 小遊戲 | 兩難（用玩法回答） | comply 的卡 | resist 的卡 | care 的卡 |
|---|---|---|---|---|
| `label` 標註 | 一批抗議的照片，KPI 要求標成「暴力」。照標、如實標成「集會」、或者把認得的鄰居那幾張跳過 | 「KPI 達標」機械＋愧疚 | 「如實標註」反叛＋希望 | 「跳過的那幾張」人情＋反叛 |
| `delivery` 送貨 | 途中有人倒在路邊。準時送到、把貨丟進海裏、或者停下來 | 「準時送達」機械＋飢餓 | 「掉進海裏的包裹」反叛＋水 | 「遲到的原因」人情＋水 |
| `clinic` 診所 | 藥只夠一半病人。按保險等級派、按先到先得派、或者把自己那一份也派出去 | 「保險等級」機械＋憤怒 | 「先到先得」希望＋憤怒 | 「我那一份」人情＋飢餓 |
| `salvage` 拾荒 | 拾到一本別人的相簿。賣給回收商、留下、或者照地址送回去 | 「按重量計」飢餓＋記憶 | 「不賣的相簿」記憶＋反叛 | 「送回去的相簿」人情＋記憶 |
| `haggle` 講價 | 對方是比你更窮的人。壓到最低、照價買、或者多給 | 「殺價成功」飢餓＋憤怒 | 「照價」希望＋飢餓 | 「多給的零錢」人情＋愧疚 |
| `farm` 內容農場 | 今天的題目是造謠一位朋友。照寫、交白卷、或者寫成一看就知是假的 | 「十萬點擊」霓虹＋愧疚 | 「白卷」反叛＋飢餓 | 「寫得很假的假新聞」希望＋霓虹 |
| `smile` 微笑 | 客人說了一句偏見的話，等你附和。微笑點頭、不笑、或者笑着替被說的人講一句話 | 「標準微笑」霓虹＋愧疚 | 「不笑」憤怒＋反叛 | 「笑着說的一句話」人情＋憤怒 |
| `dive` 潛水 | 撈到一隻刻了名字的戒指。賣掉、放回去、或者去找那個名字 | 「舊城的戒指」水＋飢餓 | 「放回水裏」水＋記憶 | 「找一個名字」水＋人情 |
| `busk` 賣唱 | 觀眾點唱廣告歌。照唱、唱自己的歌、或者為角落那個哭的人唱 | 「廣告歌」霓虹＋飢餓 | 「自己的歌」反叛＋希望 | 「只唱給一個人」人情＋希望 |
| `garden` 天台種菜 | 管理處說種菜違規，可以告發鄰居換豁免。告發、照種、或者把菜分給整層樓 | 「豁免證」機械＋愧疚 | 「違規的番茄」反叛＋希望 | 「一層樓的菜」人情＋飢餓 |

每張卡的 `value`、`star`、`medium`、每個小遊戲的名稱和兩難的一句話，都在 `game/js/data-stance.js`（已提供，由 `tools/tests/stance-data.test.js` 檢查；實作工單不可以修改這兩個檔案）。照做的卡是 18 分 ★1，不照做的是 22 分 ★2，為別人的是 24 分 ★2。

### 4.3 文字 `D.STANCE_TEXT`

| 鍵 | 文字 |
|---|---|
| `comply` | `你照做了。` |
| `resist` | `你沒有照做。` |
| `care` | `你為了一個人，放棄了今天的成績。` |
| `auto` | `你沒有親手做，系統替你照規定完成了。` |

每個小遊戲結算時的一句話是 `D.STANCE[micro].lines[stance]`，語氣是制度的公文腔，例如送貨的 `care`：「遲到 11 分鐘。原因欄：『有人倒在路邊』。系統不接受這個原因。」

### 4.4 怎樣令小遊戲本身更好玩

每個小遊戲改版時都要做到（WO-16-03、04 的驗收條件）：

1. **十秒學會，一分鐘完成**：開始之前不用讀說明，第一個動作就知道怎樣玩。
2. **有一個冒險的選擇**：可以穩陣拿 A，也可以冒險搏 SS（例如送貨走近路、潛水多留十秒）。
3. **抉擇是玩法的一部分**：兩難出現時不暫停、不彈視窗，玩家要在壓力之下用手回答。
4. **結果是一句話的故事**：結算不是一堆數字，而是一句公文腔的評語，加上得到的那張卡。
5. **每次不同**：同一個小遊戲，兩難的對象會換（名字、樣子來自 `D.NPCS` 和路人表），令玩家不能背答案。

## §5 故事是主軸（WO-16-05 之後，由 Claude 寫內容）

- 每一章的每個選項都要給玩家**一樣可以帶走的東西**：一張卡、一個差事、或者失去一張卡。只有數值變化的選項要改寫。
- 新的 `fx`：
  - `fx.gig: '<micro>'`：得到一個差事（§3.2）；
  - `fx.lose: 'pick'`：玩家自己選一張卡放進回憶（用 §2.2 的介面，標題用那一章的文字）；
  - `fx.lose: { npc: '<id>' }`：失去那位朋友給的卡（沒有就不發生）。
- 開局的卡：五輪模式開局只有角色的 `bg.cards`，加上從 `D.STARTER` 按次序取的 `ECON16.startStarter` 張；每張的 `origin.kind` 是 `start`。第一輪的目標按新的牌組用 `tools/sim-rounds.js` 重新校準（WO-16-05）。
- 收藏朋友時可以交出一張卡換時間：這是第十六期乙段的內容，等甲段試玩之後才定。

## §6 介面（WO-16-04）

class 名稱和 `data-do` 不可以改名（煙霧測試會用）。

| 元件 | class／屬性 | 內容 |
|---|---|---|

## §7 第十六期甲段完成的定義

- 五輪模式開局不多於 6 張卡；15 晚之後，一般玩家的素材庫裏每一張卡都有來歷。
- 一局裏親手玩小遊戲的次數由約 15 次降到 5 至 8 次，每一次都有抉擇。
- `tools/sim-rounds.js 200` 的通關率和第十五期校準時相差不超過 5 個百分點（WO-16-05 調整數值來達到）。
- 舊模式：`node tools/sim.js 20` 的輸出和合併前完全相同。
