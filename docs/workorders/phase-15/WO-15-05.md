# WO-15-05：篩選日與日子推進

| 項目 | 內容 |
|---|---|
| 期數 | 第十五期（總規格 §9、§10） |
| 依賴 | WO-15-03、WO-15-04 |

| 不可以改 | 其他所有檔案 |

## 目標

完成一局的閉環：篩選日（交租、靈魂秤重、機會、結局）和 `advance`（到下一晚的白天）。完成後，Node 可以由開局自動玩到結局。

## 規格

```js
review(s)    // s.phase 必須是 'review'。按總規格 §9 執行，回傳報告：
             // { round, rent, paid, cr, soul, soulOk, lost: ['rent' | 'soul'], chances, passed, ending, lines: [...] }
             // 報告的 lines 用 ROUND_TEXT 的 rentOk / rentFail / soulOk / soulFail（把 {rent}、{soul} 換成數值；soul 取一位小數）
             // 同時 s.roundLog.push({ round, rent, paid, soul, soulOk, lost })
             // 沒有結局：呼叫 advance(s)；有結局：s.ended = ending、s.phase = 'ended'
advance(s)   // 總規格 §10（替換 WO-15-04 的簡單版本）
```

- 篩選日不呼叫 `R.makeReview`、`R.endDay`。
- 失去機會一律經 `loseChance(s, cause)`（WO-15-03），所以原因和結局一致。
- 通過的金色扭蛋券用 `R.gainTicket(s, 'gold', 1, '通過第 ' + round + ' 輪篩選')`。
- 第 5 輪：先交租和秤重；機會還有剩 → `s.ended = R.endingFor(s, 'recruited')`、`s.phase = 'ended'`（之後 `main.js` 走原有的「去還是留」流程，WO-15-08 接上）。

## 測試

### `tools/tests/rounds-review.test.js`

準備：五輪模式新局，`s.night = 3`、`s.day = 12`、`s.phase = 'review'`、`s.soul = 10`。

1. `篩選日：交租通過`：`s.cr = 500` → 錢少了 `rentOf(s, 1)`、`s.reviewsPassed === 1`、`s.runTickets.gold === 1`、之後 `s.night === 4`、`s.day === 16`、`s.phase === 'day'`。
2. `篩選日：交不起租`：`s.cr = 50` → `s.cr === 0`、`s.chances === 2`、`s.lost` 包括 `'rent'`、`s.reviewsPassed === 0`。
3. `篩選日：靈魂太重`：`s.soul = 22`、`s.cr = 500` → 租照交、`s.chances === 2`、原因 `'soul'`。
4. `篩選日：兩項都失敗`：`s.soul = 22`、`s.cr = 0` → `s.chances === 1`。
5. `篩選日：最後一次機會因靈魂用完`：`s.chances = 1`、`s.soul = 22` → `s.ended.type === 'heavy'`、`s.phase === 'ended'`。
6. `篩選日：第五輪通過`：`s.night = 15`、`s.day = 60`、`s.cr = 1000` → `s.ended.type === 'recruited'`。
7b. `推進：AI 記憶消退四次、磨損減一`：`s.style = { mix: 10 }`、某張素材 `wear = 3`、另一張 `wear = 0`，`advance` 之後 `s.style.mix` 等於 `10 × 0.6⁴` 四捨五入到兩位小數（`IE.Create.newDay` 的寫法），兩張素材的磨損分別是 2 和 0。
7. `推進：水位和季節`：第 5 晚（day 20）`advance` 到第 6 晚之後 `s.day === 24`、季節和第 5 晚不同（按 `D.SEASON_ORDER` 的下一個）；水位增加「季節的 water × 4」（容許浮點誤差）。
8. `推進：過期的世界事件移除`：放一個 `until` 是 18 的事件，在第 4 晚（day 16）`advance` 之後事件不在 `s.events`。
