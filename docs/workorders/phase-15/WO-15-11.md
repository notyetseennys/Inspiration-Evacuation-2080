## 目標

令角色線、朋友線、阿星線和今日快訊在邏輯上運作：模擬器可以玩到故事的每一章，單元測試覆蓋所有規則。介面在 WO-15-13 接上。

## 規格

### 1. `game/js/story.js`（`IE.Story`，UMD，寫法照 `rounds.js`）

照總規格 §14 實作，匯出：

| 函數 | 用途 |
|---|---|
| `init(s)` | 五輪模式的 `newRun` 呼叫：設定 `s.city`（`D.CITY_DEFAULT`），建立 `s.story`、`s.nightMod`、`s.rentMod`（舊存檔沒有時，其他函數也要自動建立） |
| `plan(s)` | 每輪第一天決定本輪的收藏（§14.4.1） |
| `reversals(s)`、`reverse(s)` | 今天要發生的反轉；套用反轉（§14.3 物極必反） |
| `chapter(s)` | 今天的章（§14.3，包括城市的篩選），設 `pending` |
| `choose(s, i)` | 回答 `pending` 的章，回傳報告；極端的選項加入 `later` |
| `fx(s, option)` | 選項的效果清單（格式同 `R.optionFx`，金額已經換算；極端的選項加「物極必反」一行），給介面顯示 |
| `money(s, v)`、`fmt(s, v)`、`say(s, str, fx)` | 按城市換算金額、格式化金額、替換文字裡的佔位符（§14.3） |
| `hide(s, npc)` | 把朋友藏起來（§14.4.3），回傳 `{ ok, msg, cost }` |
| `collect(s, rep)` | 篩選日的收藏（§14.4.4），由 `IE.Rounds.review` 呼叫 |
| `astar(s)`、`feed(s)`、`fate(s)` | 阿星、今日快訊、朋友近況（§14.5） |
| `epilogue(s)` | 結局用（§14.4.5），包括「為別人」的次數 |

- 只用 `R.rand`、`R.pick`；`feed`、`money`、`fmt`、`say`、`fx`、`reversals` 都不可以用隨機數，也不改變狀態。
- 角色還沒有內容（`D.STORY.lines[bg]` 不存在）時，`chapter` 回傳 null，其他照常。
- 收藏的文字：朋友沒有這個種族的 `why`、`fate` 時（改抽其他朋友），用 `D.STORY.species[種族]` 的通用文字（§14.4.1）。
- 所有給玩家看的故事文字（章、選項、報告、反轉、結語）都經過 `say`；金額都經過 `money` 和 `fmt`。第 7 區的倍數全部是 1，所以現在的數字不變，但其他城市加入時不用再改邏輯。

### 2. 接上現有的邏輯

- `rules.js` 的 `newRun`（五輪分支）：`IE.Story && IE.Story.init(s)`。
- `rounds.js`：
  - `offer`：本輪第二天，第二張卡固定是 `friend:<本輪收藏的朋友>`（朋友不在、已經藏起來或被收藏就照舊）；
  - `choose` 的朋友卡：選了本輪收藏的朋友就記下 `met`；
  - `review`：交租和秤重之後、`advance` 之前呼叫 `IE.Story.collect(s, rep)`（機會用完時不呼叫）；
  - `target`：讀 `s.nightMod`（只影響那一晚）；`rentOf`：讀 `s.rentMod`（只影響那一輪）；
  - `fx.chance` 令機會變成 0 時，照 `loseChance` 進入「人才庫」結局。

### 3. `tools/sim-rounds.js`

- 載入 `data-cities.js`、`data-story.js`（在 `data-rounds.js` 之後）和 `story.js`（在 `rounds.js` 之後），見總規格 §2。
- 白天的流程照 §14.3：`R.morning` → `IE.Story.plan` → 有反轉就 `IE.Story.reverse` → `IE.Story.chapter`（有章就按策略選，那一天不抽道德抉擇）→ 道德抉擇 → 生活卡。
- 選章的策略（每章四至五個選項）：
  - `balanced` 選第一個 `both`；
  - `worker` 選 `survive` 之中 `cr` 最多的（可以是極端的選項）；
  - `liver` 選 `peak` 之中 `spark` 最多的（可以是極端的選項）；
  - `saint` 選 `sin` 最少的，相同時選 `atone` 最多的，再相同就選第一個；
  - `shameless` 選 `cr` 最多的；
  - `random` 用 `R.pick`。
- 藏朋友的策略：
  - `balanced`：錢夠「本輪租金 + 藏起來的費用 + 60」就藏；
  - `saint`、`liver`：錢夠「本輪租金 + 藏起來的費用」就藏；
  - `worker`、`shameless` 從不藏；
  - `random` 錢夠就用 `R.rand() < 0.5` 決定。
- 輸出多四項：每局平均回答幾章、每局平均選了幾個極端的選項、平均發生幾次反轉、朋友被收藏／藏起來的平均人數。
- 跑 `node tools/sim-rounds.js 200`，把結果和 WO-15-09 的數字並排寫在 `CALIBRATION.md` 新的一節，並對照 `docs/ECONOMY.md` 第四節的「比較輕鬆」驗收線。**不要調整 `ECON`**：如果勝率或驗收線離開範圍，在提交訊息寫明，由 Claude 決定。

### 4. 單元測試 `tools/tests/story.test.js`

1. 新局有 `s.city`、`s.story`；舊存檔（刪掉 `s.story`、`s.city`）呼叫任何函數都不會出錯。
2. 每輪第一天有章，同一天重複呼叫回傳同一章；回答之後 `done`、`log`、`side` 正確，`pending` 清除。
3. `if`、`unless`：第 1 輪的選擇令第 2 輪出現不同的章（用 `copywriter`）。
4. 城市：章的 `city` 不包括 `s.city` 時不出現（測試裡臨時加一座城市和一章，測完刪除）。
5. 每一種 `fx` 都正確套用（錢、火花、靈魂、素材、物件、配色、熟絡度、機會、`target`、`rent`、`notice`、`set`）。
6. 換算：臨時加一座 `econ` 不是 1 的城市，`money` 的收入乘 `pay`、支出乘 `price`、再乘 `inflation` 的（輪 − 1）次方；`fmt` 乘 `currency.rate`、加千位逗號；`say` 替換 `{cr}`、`{rent}`、`{city}`、`{currency}`。
7. 光譜：`survive` −1、`peak` +1、`both` 和 `others` 0，極端的選項加倍；`epilogue(s).others` 是「為別人」的次數。
8. 物極必反：選了極端的選項，`later` 有一項；未到那一輪 `reversals` 是空的；到了那一輪第一天 `reversals` 有一項；`reverse` 套用 `later.fx`、從 `later` 移除、回傳報告；再呼叫回傳 null。
9. `target` 只影響下一晚；`rent` 只影響本輪。
10. 收藏預告：同一個種子結果相同；候選按 `collectors`；候選都不在浮城時改抽其他朋友，文字用種族的通用文字；一位朋友都不在就沒有收藏；第 5 輪沒有。
11. 第二天的生活卡有這位朋友的朋友卡；選了之後記下 `met`。
12. `hide`：扣錢（經 `money` 換算）、錢不夠失敗、篩選日不會被收藏、`notice` 加一。
13. `collect`：見過最後一面得到贈物；沒見得到紙條素材；朋友 `alive` 變成 false；下一晚 `fate` 有近況。
14. `astar`、`feed`：對應正確；`feed`、`money`、`fmt`、`say`、`fx`、`reversals` 前後 `rngState` 和 `s` 都不變。
15. 「存檔再載入」（JSON）之後，`pending` 的章和未發生的反轉仍然在，可以回答、可以套用，不會重複套用。
16. `epilogue`：結語按旗標選擇；朋友的狀態、光譜和「為別人」的次數正確。
