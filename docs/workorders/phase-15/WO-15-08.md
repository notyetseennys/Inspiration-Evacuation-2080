## 目標

一局五輪模式可以完整玩到任何結局，畫面只顯示五輪模式需要的資訊。

## 規格

### 1. 篩選日（`main.js` 的 `roundsReview()`、`ui.js` 的 `roundReviewModal(rep)`）

- `roundsReview()`：`const rep = IE.Rounds.review(s)`，存檔，顯示 `UI.roundReviewModal(rep)`。
- 視窗 `.rd-review`：
  - 標題「第 X 輪・篩選日」。
  - `.rr-rent`：交租那一行（`rep.lines` 的第一行），交不起時紅色。
  - `.rr-soul`：秤重那一行，配一個天秤圖示：靈魂超過 21 克時天秤傾側。
  - 結果印章：兩項都通過「通過」（綠色），否則「失去機會」（紅色）；下面顯示剩下的機會 ●●○。
  - 按鈕 `[data-do="next"]`：沒有結局時文字 `ROUND_TEXT.nextRound`（下一輪的數字），之後 `roundsGo()`；`recruited` 時文字「探射燈停在你的窗外」，之後 `chooseToGo()`；其他結局文字「看結局」，之後 `finishRun(s.ended)`。
  - 音效：通過 `A.sfx('combo')`；失去機會 `A.sfx('stamp')`。
- `roundsGo()` 的 `'ended'` 分支：`s.ended.type === 'recruited'` → `chooseToGo()`；否則 `finishRun(s.ended)`。

### 2. 狀態列（`ui.js` 的 `renderHud`，五輪模式的分支）

- 顯示：錢、火花、靈魂（`X / 21 克`，超過時紅色）、`.chip.chances`（●●○）、`.chip.night`（`第 k／15 晚`）、`.chip.rent`（`租金 $X`，錢不夠時黃色）。
- 不顯示：身體、偏執、樓層、水位、季節倒數、下次交租日、本季訊號與門檻、能力值按鈕。
- 舊模式的狀態列完全不變。

### 3. 隱藏舊系統（只在五輪模式）

- 畫面切換列 `#views` 隱藏，畫面固定在浮城。
- 早上的手機、浮城百貨、畫廊、古董市場、家具、人脈、旅行的入口都不出現。
- 結局後的摘要（`finishRun` 的 `.run-sum`）：`通過 X / 5 輪・完成 N / 15 晚` + 用時。
- 對局紀錄（`ui-roster.js` 的歷史列）：模式名稱用 `D.MODES[h.mode].name`（五輪模式顯示「五輪」）。

### 4. 煙霧測試（延伸 `tools/smoke-rounds.js`）

13. 用自動方式（白天照舊做第一張可用的小遊戲卡；夜晚用 `bestPlay`；市集不買）玩完第一輪，到第 3 晚的市集時把 `s.cr` 設為 0，離開市集：看到 `.rd-review`，`.rr-rent` 有「交不起租」，機會變成兩次。
14. 按 `[data-do="next"]`：看到第 4 晚的 `.rd-day`；狀態列的 `.chip.night` 是「第 4／15 晚」、`.chip.chances` 有兩個實心點。
15. 結局：把 `s.chances` 設為 1、把今晚目標設為 1e15，完成一晚：結束面板按鈕是「看結局」，按下之後看到結局畫面（`.ending`）和人類樣本檔案。
16. 手機寬度（390px）：白天、市集、篩選日三個畫面 `document.documentElement.scrollWidth <= 390`。
17. 沒有 JS 錯誤。

### 5. 白天面板的兩項修訂（WO-15-06 審核後加入）

1. **第一屏看到三張卡**：桌面 1280×800 時，三張生活卡現在在第一屏以下，要捲動才看到（舊模式的行動卡也一樣，但五輪模式每天最重要的決定就是這三張卡）。五輪模式的白天要在不捲動的情況下看到三張卡的名稱：隱藏 `#views` 之後，再把浮城的舞台縮矮（例如五輪模式在 `<body>` 加 class `mode-rounds`，白天時限制舞台的高度），或者其他只影響五輪模式的做法。舊模式的版面不變。
2. **整輪預告外星評審**：外星評審的規則現在開局就選好（`s.bosses`，見總規格 §4）。白天面板在每輪的第一、二晚，於「今晚」那一行下面多一行 `.rd-boss-ahead`：文字 `ROUND_TEXT.bossAhead`，`{rules}` 換成本輪的規則「名稱」（說明），多條規則用「、」分隔，用 `IE.Stages.bossesFor(s, 本輪 − 1)` 讀取。外星評審之夜照舊寫在「今晚」那一行，不重複。`.rd-map` 每輪評審之夜的小點，`title` 也加上規則名稱。這樣玩家在市集就可以避開本輪評審討厭的素材。

煙霧測試再加兩項：

18. 桌面 1280×800、第 1 晚的白天：每張 `.rd-card .rd-name` 的 `getBoundingClientRect().bottom` 不大於 800（不需要捲動）。
19. 第 1 晚的白天有 `.rd-boss-ahead`，文字包含 `IE.Stages.bossesFor(s, 0)[0].name`；第 3 晚（外星評審之夜）的白天沒有 `.rd-boss-ahead`。

### 6. 篩選日的重新載入（WO-15-07 審核後加入）

`IE.Rounds.review(s)` 一執行，狀態就已經進入下一輪。如果玩家在篩選日的視窗重新載入，就再也看不到交租和秤重的結果。做法：

1. `IE.Rounds.review(s)` 把回傳的報告同時存在 `s.reviewRep`；新增 `IE.Rounds.ackReview(s)` 清除它（新局 `s.reviewRep = null`）。
2. `roundsGo()` 先檢查 `s.reviewRep`：有的話先顯示 `UI.roundReviewModal(s.reviewRep)`；按 `[data-do="next"]` 時呼叫 `ackReview`，再照 §1 的規則繼續。
3. `rounds-review.test.js` 加一項：篩選日之後「存檔再載入」，`s.reviewRep` 仍然在，`ackReview` 之後清除。
4. 煙霧測試：在 `.rd-review` 出現時重新載入、按「繼續」，仍然看到 `.rd-review`。

（WO-15-07 審核時已經令創作桌在五輪模式每一筆之後存檔：`IE.Game.save`。）
