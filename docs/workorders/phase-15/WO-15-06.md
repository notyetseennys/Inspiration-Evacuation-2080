## 目標

玩家可以開一局五輪模式，看到白天的三張生活卡並完成白天，進入創作桌。（創作桌之後的市集、篩選日在 WO-15-07、WO-15-08；這張工單完成時，第一晚結束後可以暫時回到白天。）

## 規格

### 1. 流程驅動（`main.js`）

新增以下函數；**舊模式的流程一行都不改**：

```js
function roundsGo()        // 按 s.phase 分派：'day' → roundsDay()；'night' → roundsNight()；'shop' → roundsShop()；
                           // 'review' → roundsReview()；'ended' → 結局（WO-15-08 接上；這張工單先呼叫 finishRun(s.ended)）
function roundsDay()       // 1. R.morning(s)（天氣、事件）；2. R.drawDilemma(s) 有就沿用 morningDilemma 的介面，處理完回到 roundsDay；
                           // 3. UI.setPanel(UI.dayPanel(s), handlers)；4. 畫面固定在浮城（Scenes.City）
function roundsChoose(id)  // IE.Rounds.choose(s, id)：
                           //   { micro } → 彈出「親手做／照舊做」視窗（[data-do="byhand"]、[data-do="byauto"]，文字用 ROUND_TEXT.byHand、byAuto，
                           //               評級用 IE.Auto.target(s, kind)）；親手做 → doAction(kind)；照舊做 → doAction('auto:' + kind)
                           //   朋友卡 → 先開 UI.talkModal（沿用聊天的對話和三種回應），按回應後才 choose(s, 'friend:<npc>', reply)
                           //   { trip } → 彈出五張素材，選兩張（每選一張呼叫 tripPick），完成後報告
                           //   其他 → 報告視窗 → maybeEncounter → roundsGo()
function roundsNight()     // IE.Rounds.startNight(s)；openCraft()
```

- 這張工單先寫兩個**暫時的版本**（WO-15-07、WO-15-08 會取代）：
  - `roundsShop()`：`IE.Rounds.shopOpen(s); IE.Rounds.leaveShop(s); roundsGo();`（直接離開市集）。
  - `roundsReview()`：`IE.Rounds.review(s); roundsGo();`（直接完成篩選日）。

- `newGame`：五輪模式呼叫 `roundsGo()`，不呼叫 `startDay()`。
- `resumeRun`：五輪模式：有 `s.session` → `openCraft()`；否則 `roundsGo()`。
- `afterSlot`：五輪模式在函數開頭：`IE.Rounds.afterDay(s); return roundsGo();`（小遊戲和照舊做的報告、奇遇之後都會走到這裡）。
- `openCraft` 的完成回呼：五輪模式不開遺物攤，直接 `roundsGo()`（市集在 WO-15-07）。
- 測試用的鉤子：`Game.newGame = newGame`（和現有的 `Game.applyMicroResult` 一樣）。

### 2. 白天面板（`ui.js` 的新函數 `dayPanel(s)`）

由上至下：

1. **一輪的進度** `.rd-map`：五輪 × 三晚的小點（`.rm-night.k-small` 等）；已完成的加 `.done` 或 `.fail`，今晚加 `.now`。旁邊寫 `ROUND_TEXT.dayTitle`。
2. 今晚：`ROUND_TEXT.tonight`（種類用 `ROUND_TEXT.nightKinds`，目標用 `IE.Rounds.target(s)`，千位分隔）。外星評審之夜加上規則名稱。
3. 租金：`ROUND_TEXT.rentLine`（每輪最後一晚的 `day`）。
4. 天氣與世界事件：一行，沿用 `R.weatherOf(s)` 的名稱和 `D.weatherNote`，以及 `R.eventsInfo(s)` 的第一項。
5. 標題 `ROUND_TEXT.dayAsk`，下面三張卡 `.rd-card[data-card]`：種類標記 `.rd-kind.k-<kind>`（文字 `ROUND_TEXT.kinds`）、名稱、說明、效果（沿用 `fxHtml`）、致命危險（紅色）、不可以選的原因（`disabled`）。
6. 兩個按鈕：`[data-do="reroll"]`（`ROUND_TEXT.reroll`，錢不夠時 `disabled`）、`[data-do="skip"]`（`ROUND_TEXT.skip`）。

- 種類顏色：工作 `#37c3d6`、虧心 `#ff4d5e`、生活 `#9be36b`、朋友 `#ff8fd1`、義工 `#f3e9d2`、出國 `#ffd36b`。
- 手機（寬 390px）三張卡直向排列，按鈕至少 44px 高，沒有橫向捲動。
- 報告視窗：五輪模式不顯示身體的變化（`reportModal` 略過 `stat === 'body'` 的項目）。

### 3. 煙霧測試 `tools/smoke-rounds.js`（新檔，結構照 `tools/smoke.js`）

- **必須固定隨機數**：照抄 `tools/smoke.js` 開頭的 `page.addInitScript`（`SEED` 環境變數），令每次測試走同一條路，不會因為隨機事件偶爾失敗。

這張工單先做到：

1. 開新局（`window.__IE.Game.newGame('copywriter', 'storm', { mode: 'rounds' })`，`localStorage` 設 `ie2080.noEncounter`）。
2. 看到 `.rd-day` 和三張 `.rd-card`；`.rd-map .rm-night` 有 15 個。
3. 按「換一批」：錢少了 `ECON.offerReroll[0]`。
4. 找一張小遊戲卡（沒有就換一批直到有）按下，再按 `[data-do="byauto"]`，按報告的確定，之後創作桌（`#ctable`）打開。
5. 沒有 JS 錯誤。
