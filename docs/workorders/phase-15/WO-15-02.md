## 目標

實作白天的純邏輯：出三張生活卡、換一批、選卡、套用結果、睡懶覺。介面在 WO-15-06。

## 規格

在 `IE.Rounds` 加入：

```js
offer(s)               // 回傳 s.offer；這一晚還沒有就按總規格 §7 的出牌規則產生（用 R.rand / R.pick）
offerCost(s)           // 換一批的價錢：ECON.offerReroll[min(rerolls, 長度 − 1)] × stakeMod(s, 'prices')，四捨五入
rerollOffer(s)         // 錢夠：扣錢、rerolls + 1、重新出三張（可以和之前相同）→ { ok: true }；不夠 → { ok: false, msg: '換一批要 $X' }
cardList(s)            // 這一晚可以出現的全部卡 id（已展開 friend:<npc>、trip:<origin>）
cardInfo(s, id)        // 介面用：{ id, kind, kindName, name, sub, micro, fx: [[種類, 文字]], danger: 數字或 0, enabled, reason }
choose(s, id, reply)   // 選卡（必須是 s.offer.ids 之一，而且 s.phase === 'day'）；reply 只用於朋友卡（聊天的回應）
                       //   有 micro → 記下 s.offer.chosen = id，回傳 { micro: kind }（由介面開小遊戲或照舊做）
                       //   friend / volunteer / trip → 即時套用，回傳報告（R.report 格式），並呼叫 afterDay(s)
afterDay(s)            // 白天完結：s.phase = 'night'。如果 s.body <= 0（世界事件中的致命危險），結局 R.endingFor(s, 'death')，s.phase = 'ended'。
                       // 可以重複呼叫：s.phase 已經不是 'day' 就甚麼都不做
skipDay(s)             // 睡懶覺：R.addSpark(s, ECON.skipSpark, true)，呼叫 afterDay，回傳報告
tripPick(s, idx)       // 出國的第二步，見下面
```

### 各種卡的套用

| 卡 | 套用 |
|---|---|
| 小遊戲卡 | 介面負責開小遊戲或 `IE.Auto.apply(s, kind)`；套用之後介面呼叫 `afterDay(s)`。`choose` 本身不改變狀態（除了 `s.offer.chosen`） |
| `friend:<npc>` | 錢不夠 `R.chatCost(s)` 時 `enabled = false`、`reason = '沒錢請人喝東西'`。套用：記下 `D.TEACH[npc]` 這個配色的等級，`R.applyChat(s, npc, reply)`（`reply` 由介面傳入，Node 測試用 `undefined`；`applyChat` 本身有機會已經升級）。如果等級沒有變，再呼叫 `R.teach(s, npc, 1, rep)`。結果：**每張朋友卡剛好升一級**（覺醒的 AI 照舊學不到）。`teach` 已經會在報告加「技法提升」一行，不要重複 |
| `volunteer` | `R.applyVolunteer(s)` |
| `trip:<origin>` | 錢不夠 `ECON.tripCost × stakeMod(s, 'prices')` 時不可以選。套用：扣錢、火花 +0.4、從 `D.CARDS` 中 `origin === <origin>` 而且不是極稀有的素材抽 5 張不同的，存在 `s.trip5 = { origin, ids: [...] }`，回傳 `{ trip: true }`；之後介面讓玩家選 `ECON.tripPick` 張，每選一張呼叫 `tripPick(s, idx)`（`R.addCard`），選夠之後清除 `s.trip5` 並呼叫 `afterDay(s)`。`s.visited[origin] = (s.visited[origin] || 0) + 1`、`s.stats.trips++` |

### `cardInfo` 的 `fx`

用 `R.actions(s)` 找同一個 id 的行動，沿用它的 `name`、`sub`，`fx` 只保留 `cr`、`spark`、`soul`、`card` 四種（不要 `body`）。`enabled`／`reason` **不沿用** `R.actions` 的 `reason`（它包括能力值和身體的條件）；只看三件事：被世界事件關閉、被 AI 取代、錢不夠（朋友卡、出國卡）。朋友卡：`fx = [['cr', '−$15'], ['spark', '+0.4 起'], ['card', '人情'], ['note', '技法：<配色名稱> +1']]`。出國卡：`fx = [['cr', '−$120'], ['spark', '+0.4'], ['card', '<地區>素材 五選二']]`。外出的工作（`D.OUTDOOR` 包括的 id）有致命危險時 `danger = R.outdoorRisk(s)`，`fx` 加 `['danger', '致命 X%']`。

## 測試：新檔 `tools/tests/rounds-day.test.js`

1. `白天：三張不同的卡`：`offer(s).ids` 長度 3、互不相同；第一張的種類是 work 或 shady；第二張是 life 或 friend。
2. `白天：同一晚出牌不變`：連續呼叫兩次 `offer(s)` 回傳相同的 `ids`。
3. `白天：同一個 seed 出牌相同`：兩局 seed 相同的新遊戲，`offer` 完全相同。
4. `白天：換一批要錢`：`s.cr = 100` 時 `rerollOffer` 成功並扣 `ECON.offerReroll[0]`；`s.cr = 0` 時失敗，錢和出牌都不變。
5. `白天：第一輪沒有出國`：第 1 至 3 晚各重抽 50 次，沒有出現 `trip:` 開頭的卡。
6. `白天：被 AI 取代的工作不出現`：`s.removed.label = true` 之後重抽 50 次，沒有 `label`。
7. `白天：朋友卡必定教技法`：選 `friend:ho`（需要時直接把 `s.offer.ids` 設為 `['label', 'friend:ho', 'volunteer']`），之後 `s.forms.mono === 2`、錢少了 `R.chatCost(s)`、`s.phase === 'night'`。
8. `白天：義工令靈魂變輕`：選 `volunteer` 之後 `s.soul` 下降、`s.phase === 'night'`。
9. `白天：小遊戲卡交給介面`：選 `label` 回傳 `{ micro: 'label' }`、`s.phase` 仍然是 `'day'`；之後 `IE.Auto.apply(s, 'label')` 和 `afterDay(s)`，錢增加、`s.phase === 'night'`、`s.body` 不變。
10. `白天：睡懶覺`：`s.spark = 2` 時 `skipDay` 之後 `Math.abs(s.spark - 2.2) < 1e-9`、`s.phase === 'night'`。
11. `白天：出國五選二`：第 4 晚（`s.night = 4`、`s.day = 16`）、`s.cr = 500`，選 `trip:asia` 之後 `s.trip5.ids` 有 5 張亞洲素材；`tripPick` 兩次之後素材庫多 2 張、`s.trip5` 清除、`s.phase === 'night'`。
