# 第十九期總規格：令遊戲更好玩（一）讀得懂的創作桌、值得買的素材包

> 2026-11-26。根據好玩度研究（`docs/research/fun-audit.md`，第十一節的修正後提案）。製作人決定「先做第 1 項的兩個修正」，由 Claude 直接實作。
> 這份文件是第十九期的規則、數值和文字的**唯一來源**；它不改動第十五至十八期的其他規則。
> 經典模式（`standard`、`long`）完全不受影響：`node tools/sim.js 20` 的輸出和基準逐字相同。

## §1 為甚麼

研究的量度（全城篩選，均衡機械人）：

- 一筆有十多個小加成浮出來（+2 倍率、承 +2、層次 +20 籌碼……），看不出哪一樣重要；下筆之前計分板只寫結構的基本值（例如 10 × 1），玩家沒有辦法比較兩種排法；五輪模式的創作桌上沒有色輪，「相鄰」「相反」要自己記；稿紙上寫「合 ×2」，實際是 ×1.5（第十七期校準之後沒有更新）。
- 市集的素材包：買了反而差 4 點通關率（74.2% 對 78.3%），因為包裏的卡令牌庫變大、變雜。實驗：改為「選一張，同時燒掉最弱的一張」之後，買包好 2 點。

## §2 讀得懂的創作桌

### 2.1 下筆之前：結構的籌碼和倍率

- `IE.Create.scorePlay(s, uids, { structOnly: true })`：只計結構的部分：素材的籌碼（星級、閃卡、磨損、回響令下一張再計一次）、結構的基本值和等級、相連的「承」、複合情緒、媒材、題材、轉、合、稱號。不計物件、流派、卡面效果（閃、燒、撕）、具名組合、舊城的「滿座」，也不乘最後的倍數（AI 模仿、評審、天氣、旅行、KPI、火花、前世）。
- `IE.Create.preview` 多回傳 `structChips`、`structMult`，和 `structX`（結構的 ×倍率：轉、合、稱號、張力、矛盾）。
- 創作桌的預覽列：籌碼 × 倍率顯示結構的部分；桌面逐項列出倍率（「轉 ×1.5」「合 ×1.5」「稱號 ×1.25」「張力 ×1.25」）和題材；手機（560px 或以下）只顯示合計（「結構 ×2.81」），題材不顯示。
- 物件、組合和火花仍然在下筆時才揭曉（保留驚喜；舊城節點「排練」照舊顯示預計的總分）。
- 稿紙最後的「合」寫真正的倍率：`合 ×` + `D.DESK.he`（現在是 1.5）。

### 2.2 計分演出：小加成合併成一拍

- 「承」的加法、複合情緒的加法（交融、層次）和回響、媒材、題材：不再各自一行，合併成一個會跳動的標籤：`情緒「罪與罰・抗爭・逆流…」　+14 倍率　+40 籌碼`（最多列三個名字），每一步只等 0.1 秒左右（原本 0.2 秒以上）。
- 改變局面的仍然各自一拍：轉、合、稱號、張力、矛盾（×倍率）、每一件物件和流派、具名組合、最後的倍數。
- 結果：一筆的標籤由十多個減到六、七個。規則和分數完全不變（只改演出）。

### 2.3 小色輪

- 夜景右上角（`.dk-canvas` 裏的 `.dk-wheel`，手機 64px、桌面 88px）：十種情緒按色輪的次序排成一圈，每種一個字（`D.DESK_WHEEL.short`：情、望、水、憶、叛、機、疚、怒、霓、餓）；對面的情緒之間有一條線。
- 稿紙上最後一張素材的情緒是「現在」（白邊），隔鄰的是「承」（綠邊），對面的是「轉」（橙邊，連線亮起）；手上沒有的情緒變暗。
- 不另外佔高度（創作桌仍然一屏）；計分時變淡；序章不顯示。
- 文字：`D.DESK_WHEEL`（`center` 色輪、`legend` 承＝同色或隔鄰・轉＝對面、`hand` 手上 {n} 張）。
- 「玩法」的創作一段加上一句說明色輪和預覽。

## §3 值得買的素材包：選一燒一，或者跳過

| 動作 | 規則 |
|---|---|
| 買包 | 和以前一樣：撕開三張（舊城「潮汐表」四張）；`s.pack.paid` 記下付了多少 |
| 選一張 | `IE.Rounds.packPick(s, i, burnUid)`：收下第 i 張；`burnUid` 不是 `null` 時，同時從素材庫燒掉那一張 |
| 不可以燒 | 愧疚素材；剛選中而會升星的那一張（重複的素材是原來那張升星）；燒掉之後素材庫少於 `ECON.minDeck`（8 張） |
| 跳過 | `IE.Rounds.packSkip(s)`：一張都不收，拿回 `floor(付了的錢 × D.PACK16.skipRefund)`（一半） |

- 介面（`IE.UI.packModal(s, { chosen, opened })`、`main.js` 的 `roundsPack`）：第一步撕開三選一，下面有「跳過，拿回 $X」；選了一張之後是第二步「要同時燒掉一張素材嗎？」：上面是選中的卡和一句說明，按鈕「不燒，收下就好」「重新選」，下面是整個素材庫（由最弱的排起），不能燒的按鈕不能按並寫原因。返回第一步時包保持撕開。
- 文字：`D.PACK16.text`。
- 統計：`s.stats.packBurns`、`s.stats.packSkips`。
- 模擬器的機械人：素材庫超過 10 張時，選最好的一張，同時燒掉最弱的一張（星級不高於選中的；不燒愧疚、不燒會升星的那一張）。`NOBURN=1` 關掉，用來比較。

## §4 測試

- `tools/tests/packshop.test.js`（4 項）：買包記下付了多少、跳過拿回一半；選一燒一張數不變；不燒和以前一樣；不能燒的三種情況。
- `tools/smoke-rounds.js`：開包有「跳過」；選了之後問要不要燒（列出整個素材庫）；不燒多一張；第二個包選一燒一；創作桌的預覽籌碼等於結構的部分，小色輪十種情緒、最後一張亮起，「合」的倍率正確。
- 全部：`node tools/test.js` 255 項；`smoke.js`、`smoke-rounds.js`（97 項）、`first-five.js`（創作桌仍然一屏）通過；`node tools/sim.js 20` 和基準相同。

## §5 平衡的影響

| 量度 | 第十八期 | 第十九期（機械人會選一燒一） |
|---|---|---|
| 全城篩選，均衡 300 局 | 75.3%（`NOBURN=1`，同一批種子） | **83.0%（+7.7）** |
| 浮城年表，均衡 48 個生涯：第一次挑戰失敗（第一至五季） | 98%、98%、92%、85%、92% | 96%、100%、92%、88%、98% |
| 浮城年表，均衡：要幾生通過（第一至五季） | 4、5、3、3、5（第 21 生通過五季） | 3、5、4、3、4（第 20 生） |
| 浮城年表，新手 36 個生涯：通過五季 | 第 38 生 | 第 37 生 |

- 素材包由「買了反而差 4 點」變為**值得買**（選一燒一比不燒多 7.7 點）。
- 第十八期「失敗是必然」的校準基本不變（誤差之內），不用重新校準。
- 全城篩選的均衡由約 76% 升到 83%，高於第十七期定的 65% 至 75%。全城篩選是通過第四季之後的自由模式；要收緊的話，可以只給全城篩選一個目標倍率（例如 ×1.1），不影響季節。**等製作人決定。**
- 計分演出、預覽和色輪只改畫面，不改分數。
